## Quick security findings

**No obvious credential-exfiltration or remote-code-loading behavior was found in
the reviewed custom source and startup/build paths. This is not a malware-free
certification.** The review did not run Yuri, sign in, contact a game server, build
the donor, download release binaries or analyze bundled native/JAR machine code.

1. **Account tokens are insufficiently protected on disk.**
   `api/gui/alt/YuriAltMenu.java:608` writes access tokens directly into
   `<gameDir>/Yuri/alts.txt`. Refresh tokens in `tokens.txt` use repeating XOR with a
   constant public key followed by Base64 (`TokenEncryption.java:8–29`). Anyone
   able to read those files can recover the credentials. These weaknesses predate
   1.3; the account menu rewrite still retains them. Do not reuse this storage design.

2. **OAuth lacks callback binding.**
   `MicrosoftOAuthTranslation.java:101,190,216` uses a localhost listener, which
   is good, but the authorization request has no state/PKCE and the handler accepts
   any GET containing `code`. A client secret is embedded in the source and sent
   in the browser authorization URL. Local callback interruption or sign-in
   confusion is a concern; account takeover was not demonstrated. This design
   predates 1.3. The actual 1.3 change adds defensive JSON/null handling.

3. **Dependencies still have published advisories.**
   An online OSV query of 36 explicitly declared Maven coordinates matched
   **22 advisory/package pairs across 9 coordinates**. See
   [the saved dependency evidence](YURI_1_3_DEPENDENCIES_2026-10-10.json), including
   advisory IDs, version ranges, summaries and references. These are package
   matches, not 22 proven exploitable client paths. No transitive dependency graph
   was resolved.

   | Declared dependency | Advisory matches |
   | --- | ---: |
   | Netty `4.0.23.Final` | 1 |
   | HttpClient `4.3.3` | 3 |
   | Commons Compress `1.8.1` | 6 |
   | Log4j API `2.24.1` | 1 |
   | Log4j Core `2.24.1` | 4 |
   | Guava `17.0` | 3 |
   | Commons Lang3 `3.3.2` | 1 |
   | Commons IO `2.4` | 2 |
   | Gson `2.2.4` | 1 |

   Yuri upgraded Log4j from `2.0-beta9` to `2.24.1`, addressing the old dependency,
   but 2.24.1 is not advisory-free today. The newer matches concern TLS appenders,
   XML/syslog layouts and MapMessage JSON handling; those features' reachability
   in Yuri was not established. Apache's
   [security advisories](https://logging.apache.org/security.html) describe the
   configuration conditions. This is a dependency follow-up, not a claim that
   Minecraft chat can execute code through this release.

4. **New Auto Server behavior needs tighter boundaries if reimplemented.**
   `AutoServerModule.java:69,107–119` has a shared default registration password
   and responds to chat containing registration keywords. New policy/report/excuse
   actions can send messages without a separate per-action decision; the report
   thread does not capture a native activation/world owner. Keep any reimplementation
   explicitly configured, throttled and activation/world scoped. No messages were
   sent during this review.

Reviewed network destinations have recognizable feature purposes: Microsoft/Xbox/
Minecraft authentication, GitHub configs, mc-heads avatars, NameMC/custom skin and
custom image URLs, and Apple artwork search. MediaTracker's existing PowerShell/
playerctl processes retrieve local media metadata; the OAuth processes open a browser.
No new tracked JARs, native binaries, launch scripts, workflows or wrapper files
changed between v1.2.0 and v1.3.0. Their unchanged state is not binary security proof.
