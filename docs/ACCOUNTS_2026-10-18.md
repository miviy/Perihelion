# Native account manager

Open **Accounts** from the main menu, Multiplayer or Singleplayer, or run
`.accounts`. Log out of a world before changing sessions. All account screens use
the ClickGUI/Adjust font, text style, accent, selection colors, panel opacity,
background opacity and scale. These are the existing client settings and presets;
there is no separate account-manager theme to keep in sync.

The main screen keeps one full-width account list and three primary actions:
Log in, Add account and More. Right-click a row for check/pin/copy/removal;
More contains profile tools, stores, save launcher and undo. Account screens use
quiet headers, flat navigation, consistent content insets and field padding.
The disconnected store form contracts to its content instead of leaving a large
empty panel. Fields, hit areas and selected-font caret placement share the same
padding.

## Features

- Search names/types, pinned-only filtering, pinned-first saved/A-Z order,
  virtualized scrolling, active-session marking, account validation, save launcher,
  copy name, confirmed removal and one-step undo while the screen stays alive.
- Up/Down, Page Up/Down, Home/End select and reveal accounts; Enter logs in;
  Ctrl+F focuses search; Ctrl+C copies a selected name; Delete removes with
  confirmation; Ctrl+Z restores; Ctrl+Up/Down reorder within a pin group when
  using unfiltered saved order. Escape clears search, then returns to the parent.
- Microsoft device-code sign-in and browser sign-in, with a loopback-only,
  state-checked callback, PKCE and five-minute timeout; existing launcher session
  capture; username-only offline accounts; Minecraft access tokens; refresh-token
  single/clipboard/text-file imports; Netscape/JSON/header cookie imports and
  bounded `.txt` folder imports.
- Access-token validation precedes refresh. Both Microsoft OAuth clients and
  their distinct Xbox ticket prefixes are supported. Rotated tokens are saved
  before Xbox/profile work. Interrupted sign-ins can be resumed, and refresh
  imports remember rotated replacements. The worker serializes refreshes.
- Name availability, confirmed name changes, public name history, skin lookup by
  username or HTTPS texture URL, PNG upload, classic/slim model selection, preview,
  named favorites, optional default skin for newly added online accounts, and a
  persistent local-only skin override with texture cleanup.
- Observed Hypixel bans and duration: only recognized Hypixel hosts contribute
  status; a successful join records that fact. An account without observed data
  remains unchecked; an elapsed duration asks the player to recheck by joining.
- Localts, Nicealts and Fernan Club share connection, balance/stock, category/name
  search, quantity limits, price confirmation, order history and per-delivery item
  selection/import. Localts quantity discounts and asynchronous packaging,
  Nicealts custom server/protocol/chat purchases and subscription generation,
  Fernan cooldown/purchase limits, Peso redemption and dead-item refund requests
  have dedicated compact forms.
- Paid responses are journaled before import or a subsequent charge. A durable
  fingerprint ledger skips previously imported/dead items even after account
  removal. Hold Shift when viewing a single order to retry its items, or Shift
  when scanning history for a full retry scan. Ordinary scans stop after twelve
  freshly read orders without new accounts; cached deliveries avoid order reads.
  History scanning is cancellable, paced and resumes from its encrypted journal.
  Non-idempotent purchase/redemption/refund requests are never retried automatically.

## Storage and ownership

Private data is under the active game's `config/perihelion/accounts/`:
`accounts.vault`, `accounts.key`, and `accounts.vault.bak`. Keep the key with the
vault when making a backup. The vault uses AES-GCM with a fresh nonce, an owner-only
local key and atomic replacement. The previous ciphertext is retained. A failed
load, missing key, unknown schema or authentication failure never silently creates
a replacement over existing account data. File/response sizes, list size and
favorite count are bounded. The local key protects against accidental disclosure
of the vault alone; it is not an OS keychain or protection against software running
as the same user. Windows uses the user's profile ACL instead of POSIX permissions.

Tokens, cookie exports, store keys, recovery deliveries and favorites stay outside
shareable client configuration/presets. Response bodies and credentials are not
used in error messages. HTTP has timeouts and bounded bodies. Cookie redirects are
restricted to HTTPS Microsoft/Xbox/Minecraft sign-in hosts with per-domain/path
cookies. No donor binaries, code framework, libraries, assets, custom theme or
Windows-only DPAPI dependency are bundled.

The account service is runtime-owned. One bounded worker performs account/network
and vault work; synchronized snapshots feed the UI. Only guarded client-queue
callbacks change Minecraft's session, and the session mixin rejects connected or
off-thread mutation and clears cached profile properties. Closing screens cancels
their callbacks; shutdown cancels requests, stops the local callback server,
unregisters Forge listeners and releases skin/font textures.

## Reference and deliberate adaptations

Reference: `../alt mannges/UniversalAccountManager`,
[`sc6the/UniversalAccountManager`](https://github.com/sc6the/UniversalAccountManager),
commit `9e9b2479af877d90a4618bb4bb685009e19d789a`. Its source and decompiled
behavior were read as data. No donor build, scripts or bundled JARs were run, and
the reference checkout remains unchanged. No license file was present at this
revision; no donor code or assets were redistributed.

Perihelion supplies its own UI, account records, storage, lifecycle and protocol
adapters. The preview uses a compact skin head rather than the donor's large 3D
panel. Public name history uses Ashcon. Cookie sign-in implements the four current
Microsoft code/implicit grant attempts and form/script redirects; it does not
depend on the donor's old SISU fallback chain. Startup performs no unsolicited
account refresh, provider queries or purchases. Credentials are validated when
the player requests a check/login/import. The account limit is 5,000, favorites
50, vault 16 MiB, skin PNGs 64x32/64x64 under 1 MiB, normal store orders at most
100 items (Nicealts 10). History paging is bounded to 1,000 pages; reads are serial
and paced rather than using the donor's parallel windows.

The donor's inferred Fernan refund route remains `/store/refunds`. Authenticated
provider, browser/device, real-cookie, store-purchase, refund, remote profile
mutation and live Hypixel behavior require live credentials/network validation;
synthetic unit/native UI checks do not establish those outcomes.

rejects connected session switches and checks the transformed local skin/model
hooks. It uses only synthetic offline identities and a generated test PNG.
