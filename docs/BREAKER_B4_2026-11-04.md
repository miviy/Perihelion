## Confirmed problems repaired

The previous cover routine only considered immediate bed neighbors. It could
choose an inner block hidden behind another layer, or treat a hidden air pocket
as proof the bed was exposed. It then kept aiming through the outer cover without
ever sending a valid START. Bed-center aiming also ignored the bed's partial
height and alternate visible points.

The replacement plans toward both bed halves using real block bounds and
sensitivity-rounded rays. It traces cover voxels without mutating the world,
scores complete sampled paths by estimated mining ticks, and mines only the
first actually visible obstruction. After each break it replans. Tool strength,
harvest capability, Efficiency, Haste, fatigue, water and airborne penalties are
included in route scoring. Actual accumulated damage comes from Minecraft's
native hardness calculation with the owned tool selected.

The native session also repairs these transitions:

- Material/state changes at the same position, tool changes, server block
  corrections and lost aim/tool ownership abort and clear old progress.
- A newly visible bed retires unnecessary cover mining, as in B4's exposed-bed
  handoff, with actual visibility rather than an arbitrary neighboring air cell.
- Digging follows the matching submitted walking angle and exact visible face.
  One damage step is allowed per walking pass; no unsent angle can authorize it.
- START/STOP/ABORT packets belong to the activation and connection. B4-style
  foreign-dig suppression prevents manual mining packets from cancelling the
  task. Packet identity replaces B4's global sending flag. RELEASE_USE_ITEM and
  item-drop actions remain available.
- Cleanup retires state before sending packets. Disabling during START results
  in a final ABORT, and disabling during STOP cannot mutate a retired client task.
- Zero-hardness cover is handled as an instant break; negative-hardness and
  non-finite invalid progress are rejected. Creative sword restrictions and
  Adventure edit restrictions are respected.

## B4 comparison and intentional differences

| B4 behavior | Native implementation |
| --- | --- |
| Search both bed halves and choose an accessible target | Both halves are sampled using their actual bounds; valid orphan halves remain discoverable. |
| Break near block / fastest material using available tools | Costed visible paths extend this behavior to multiple cover layers. This fixes the single-neighbor limitation rather than copying it. |
| Tool-aware strength, Efficiency and harvest divisor | Candidate tools are scored by actual block-position hardness and vanilla conditions; native hardness accumulates the actual damage. Held-slot ties avoid unnecessary swaps. |
| START, progress, STOP, abort and short wait | Native scoped session, actual hit face, progress reset on interruption, two-update handoff (one idle input update) after completion, matching B4's wait-counter behavior. No initial five-tick delay. |
| Stop redundant cover work when the bed opens | Real ray visibility is required before handing off to the bed. |
| Suppress competing dig packets | Connection-scoped mining-only suppression with an identity set that is cleared after each send. |
| Own-bed exclusion | Existing runtime-owned home tracker and whitelist remain authoritative, including unknown-home waiting and both halves. |

Legit and Hypixel now peel reachable cover. Vanilla remains exposed-bed-only.
Existing settings and defaults are retained; no new module, dependency or setting
was added. Effective reach respects the smaller of Range and controller reach.
The visible hotbar is restored while the server tool claim remains owned during
mining. Aura's existing busy-task binding remains in place.

This is a native port of the useful B4 behavior, not an exact implementation of
all BedAura modes. Instant/Swap shortcuts, ignore-slowdown/ground-spoof options,
early STOP thresholds and skip-verification behavior were not imported. B4's
event bus, module manager, config system and global state were not copied. Native
block prediction is corrected/restarted on server block updates.

## Verification and second review

The focused packaged check is `scripts/launch-smoke --scenario breaker`.
It uses survival mode, real native hardness, owned tools and a serialized PLAY
peer. The matrix covers exposed beds; one, two and three layers; wool, planks,
end stone, stained hardened clay, glass, obsidian, mixed layers; and TNT's
zero-hardness edge case. Extra cases cover Efficiency, manual tool choice,
fatigue, air slowdown, hidden air pockets, newly opened beds, replacement blocks
and tools, server corrections, GUI interruption, unbreakable cover, cancelled
walking, foreign mining packets, item release and disabling during START.

Each START is checked against actual native tool strengths, and each STOP is
checked against the required mining time. Tests also verify look-before-dig
ordering, visible-slot preservation and scope cleanup. The existing home-bed
suite checks delayed acquisition, late enable, own/enemy halves, match reset and
world replacement. The second review rechecked these transitions against B4's
target/progress/swap lifecycle and added the exposed-bed and reentrant-disable
regressions.
