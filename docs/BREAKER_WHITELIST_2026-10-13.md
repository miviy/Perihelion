# Breaker home-bed whitelist — October 13, 2026

Implemented the whitelist follow-up from the bug review. Breaker no longer decides
which bed is home when it enables. A runtime-owned native tracker observes the
world and match while the module is disabled, then Breaker uses its current state.

## Behavior

- The first eligible input pass after a world/match reset captures the player's
  search origin. Discovery remains anchored there even if the player moves while
  the home bed or its chunk is unavailable.
- Discovery searches loaded blocks within 16 blocks of that origin. It selects
  the nearest complete bed with coherent FOOT/HEAD and facing properties. Work is
  limited to 4,096 candidate positions per input pass; an unsuccessful sweep waits
  20 input passes before retrying. No unloaded chunk is generated by discovery.
- Once captured, both halves and nearby cover positions are protected for the
  match. Toggling Breaker, moving, losing those blocks or unloading their chunk
  does not capture another bed. Enabling beside an enemy therefore preserves the
  existing home classification.
- World-generation changes/disconnects discard home, origin, candidate and world
  references. A type-1 server-system S02 message containing “Protect your bed”
  starts fresh match acquisition. Normal player-chat and action-bar messages do
  not reset it. Duplicate announcements within 20 input passes are ignored.
- With Whitelist enabled, Breaker waits while discovery is pending. With it
  disabled, existing unrestricted behavior remains available. The setting's
  tooltip explains the waiting behavior.
- A match revision change retires pending digging, rotation and tool claims.
  The action phase rechecks the revision/known home before digging, including a
  reset arriving after input preparation. It also rejects protected cover blocks.
  Native PRE ray, actual face, hardness/controller, slot and movement checks remain.

This is a spawn-proximity heuristic, not an authoritative team-bed identifier.
It assumes the player is near home on the first input after world/match start.
The start-message recognition follows the donor's English phrase. Unrecognized
or localized match messages without a world change do not establish a new match.
The fixed origin deliberately avoids retrying around a later enemy position;
an unmatched or distant spawn can leave Whitelist waiting until a recognized reset.

## Ownership and donor reference

Perihelion's registry, lifecycle, event ownership, shared controls and existing
incremental scanner were inspected first. Compared read-only Yuri v1.3.0
`6f5603e0c0eed253741bacdcd4135830c916602e`:
`managers/impl/BreakerWhitelistManager.java`, `modules/impl/player/BreakerModule.java`
and the packet/bed definitions used by them. The donor observes beds independently
of module enable and resets acquisition on the match announcement.

New HomeBedTracker/HomeBedState use a runtime-owned EventOwner, ordinary native
client events and client-thread state. They introduce no static client state,
donor managers, event bus, config or new module. Three observer subscriptions stay
installed while the runtime lives; world loss clears their data and runtime
shutdown removes all three. Faulting the tracker closes its owner, clears data
and leaves whitelisted Breaker unable to act on unknown state.

Native differences are deliberate: a fixed spawn anchor, loaded/coherent bed
validation, bounded scans, nearest-bed selection, both-half protection, system
message filtering and waiting rather than breaking unclassified beds.

## Verification

Six new unit tests cover delayed anchored acquisition, immutable home classification,
reset/reacquisition, both halves/cover, invalid pairs and runtime observer cleanup.
All **287 unit tests** pass, together with architecture/distribution checks.

HomeBedProbe exercises the transformed Minecraft world and captures real native
digging packets. It checks discovery while disabled, enabling beside an enemy,
repeated toggles at home, late home arrival after movement, loss of home blocks,
player-chat rejection, match reset between preparation/actions, next-match
acquisition, duplicate announcements, world loss/replacement and listener lifetime.
The final packaged Forge and OptiFine M5 full suites pass with the same package
and fixtures, including **26 HomeBedProbe assertions**, 106 PRE-action assertions,
306 rotation assertions and 78 compatibility assertions. Shutdown reports zero
subscriptions/queued tasks and `stdoutError=false`.

An initial fixture compile error was repaired using its established reflection
pattern. Two fixture assumptions were corrected: the listener count now includes
the runtime-owned observer, and FOOT/HEAD test beds use matching facing metadata.
After whitelist assertions first passed, the existing delayed FIFO smoke assertion
failed once; only its failure diagnostics were improved. The identical assertion
then passed in final Forge and OptiFine runs. Its initial root cause remains
unresolved, and that failed run (including `stdoutError=true`) is retained rather
than counted as successful. Exact outcomes and source/JAR hashes are in
[the evidence ledger](BREAKER_WHITELIST_VERIFICATION_2026-10-13.json).

Tests use disposable offline worlds and controlled packet fixtures. No authenticated
BedWars server or localized server announcement has been tested.
